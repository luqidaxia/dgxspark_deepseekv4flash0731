## 1. 方案概述

### 1.1 目标

在两台 DGX Spark 上部署 DeepSeek V4 Flash（DSpark 版本），通过 **Tensor Parallelism = 2** 跨双机运行，利用 RoCE 网络进行 NCCL 通信，对外提供 OpenAI-compatible API。

### 1.2 核心结论

| 项目 | 结论 |
|------|------|
| 镜像 | 必须使用 `ghcr.nju.edu.cn/anemll/dspark-vllm-gx10:0.1.1`（NJU 镜像代理）。NVIDIA 官方 / 社区镜像因缺少 SM120/121 kernel 会触发 `hc_pre` 撞墙。 |
| 启动方式 | 推荐 `docker run` 直接启动；Worker 必须加 `--headless`。 |
| 网络 | 单 lane RoCE（`rocep1s0f0`）已跑通；双 lane 可后续扩展。 |
| 关键环境变量 | `VLLM_HOST_IP`、`HEADLESS=1`、NCCL HCA/GID 必须正确。 |
| 首冷启动时间 | 约 18–20 分钟（含 NCCL init、模型加载、TileLang 编译、DeepGEMM warmup、FlashInfer autotune、CUDA Graph capture）。 |
| 验证结果 | `/v1/models` 正常返回；`/v1/chat/completions` 正常输出 Python 代码。 |

## 2. 硬件与网络拓扑

### 2.1 节点信息

| 项目 | Head（spark-3e35） | Worker（spark-cefb） |
|------|--------------------|----------------------|
| 管理口 | enP7s7：192.168.21.234/24（有线） | wlP9s9：192.168.22.161/24（WiFi） |
| SSH | 本机 | `root@<WORKER_IP>`（密码见环境变量 `WORKER_PASS`） |
| RoCE Lane 1 | enp1s0f0np0：10.10.12.11/24（rocep1s0f0） | enp1s0f0np0：10.10.12.21/24（rocep1s0f0） |
| RoCE Lane 2 | enP2p1s0f0np0：10.10.13.11/24（roceP2p1s0f0） | enP2p1s0f0np0：10.10.13.21/24（roceP2p1s0f0） |
| GPU | GB10（SM 121） | GB10（SM 121） |
| Docker | 29.2.1 | 29.2.1 |
| 模型路径 | `/data/models/deepseek-ai/DeepSeek-V4-Flash-0731` | `/data/models/deepseek-ai/DeepSeek-V4-Flash-0731` |

> **注意**：Worker 的 RoCE IP 地址可能因 NetworkManager 或重启丢失。启动前必须确认 `enp1s0f0np0` 上存在 `10.10.12.21/24`，否则 NCCL TCPStore 无法连接。可通过 `./preflight.sh` 自动检查。

### 2.2 物理拓扑

```
┌─────────────────────────────────────┐      ┌─────────────────────────────────────┐
│  DGX Spark #1 (Head: spark-3e35)     │      │  DGX Spark #2 (Worker: spark-cefb)   │
│  管理：192.168.21.234                │      │  管理：192.168.22.161 (WiFi)         │
│  RoCE：10.10.12.11 / 10.10.13.11    │◄════►│  RoCE：10.10.12.21 / 10.10.13.21    │
│  模型：/data/models/.../0731         │ 200G │  模型：/data/models/.../0731          │
│  GB10 × 1 (128 GB Unified)          │ QSFP │  GB10 × 1 (128 GB Unified)           │
└─────────────────────────────────────┘      └─────────────────────────────────────┘
```

### 2.3 网络原则

- **不要 bond**：RoCE CM 会被 bond 的虚拟 MAC 搞乱。
- **双独立子网**：Lane 1 和 Lane 2 各自独立 IP/子网。
- **MTU 9000**：两端 RoCE 接口必须设为 9000。
- **NetworkManager 不管理 RoCE 口**：避免地址被清。
- **当前用单 lane**：`rocep1s0f0`（Lane 1），后续可扩展双 lane。


国内建议通过 NJU 镜像代理；如无法访问，可配置 HTTP 代理 `172.16.1.199:1198`。

### 3.3 网络验证

```bash
# 两端都执行
ping -c 3 10.10.12.21   # Head 上 ping Worker
ping -c 3 10.10.12.11   # Worker 上 ping Head

# 检查 RoCE 接口有 IP 且 MTU 为 9000
ip -4 addr show enp1s0f0np0
ip link show enp1s0f0np0 | grep mtu
sudo nmcli dev set enp1s0f0np0 managed no

# 查看 GID 表，找到 RoCE IP 对应的 v2 index
show_gids
```

如果 Worker 的 `enp1s0f0np0` 没有 IP，先临时配置：

```bash
sudo ip addr add 10.10.12.21/24 dev enp1s0f0np0
sudo ip link set mtu 9000 dev enp1s0f0np0
sudo nmcli dev set enp1s0f0np0 managed no
```

要持久化（推荐）：

```bash
sudo nmcli connection modify enp1s0f0np0 \
  ipv4.addresses 10.10.12.21/24 \
  ipv4.method manual
sudo nmcli connection up enp1s0f0np0
```

宿主机需要：

```bash
sudo apt update
```

## 4. 环境变量配置

### 4.1 关键环境变量说明

| 变量 | 作用 | 说明 |
|------|------|------|
| `VLLM_HOST_IP` | ZMQ MQ 绑定地址 | 必须指向 RoCE IP，否则 Worker 连不上 Head。 |
| `HEADLESS` | Worker 无头模式 | Worker 必须 `HEADLESS=1`，Head 留空。 |
| `NCCL_IB_HCA` | NCCL RDMA 设备 | 单 lane：`rocep1s0f0`。 |
| `NCCL_IB_GID_INDEX` | RoCE GID index | **必须以 `show_gids` 输出为准**，不要写死。启动脚本已自动按 `show_gids` 动态计算。 |
| `NCCL_SOCKET_IFNAME` | NCCL 控制面网口 | `enp1s0f0np0`。 |
| `TP_SOCKET_IFNAME` | PyTorch TP socket | `enp1s0f0np0`。 |
| `GLOO_SOCKET_IFNAME` | GLOO socket | `enp1s0f0np0`。 |
| `VLLM_USE_B12X_MOE` | 启用 B12X MXFP4 MoE | 不开性能下降约 50%。 |
| `VLLM_TRITON_MLA_SPARSE` | FlashInfer SM120 sparse MLA | 必需。 |
| `VLLM_USE_FLASHINFER_SAMPLER` | garble fix | 必需。 |
| `DSPARK_SLOT_CLAMP` | DSpark draft slot 钳位 | anemll 推荐。 |
| `TORCH_CUDA_ARCH_LIST` | 编译目标 | `12.1a` 对应 GB10。 |

## 5. 启动方式

### 5.1 推荐：一键启动（start-all.sh）

**启动前建议先跑预检：**

```bash
cd /root/dsv4dspark
./preflight.sh [root@worker-ip]
```

`preflight.sh` 会检查：
- Worker SSH 连通性
- Head / Worker 的 RoCE 接口是否有 IP、MTU 是否为 9000
- 双向 RoCE ping
- 两端 `show_gids` 中 RoCE IP 对应的 GID index 是否有效
- 端口 8888 / 25000 是否被占用
- Docker 镜像、模型路径是否存在

如果预检发现 RoCE 配置缺失，可以：

```bash
# 手动修复 RoCE IP/MTU/NM 管理状态（可选持久化）
./setup-roce.sh [root@worker-ip]

# 或在预检时自动修复
./preflight.sh [root@worker-ip] --auto-fix
```

预检通过后，在 Head 节点执行：

```bash
cd /root/dsv4dspark
./start-all.sh [root@worker-ip]
```

默认 Worker 通过 SSH 连接，密码通过环境变量 `WORKER_PASS` 设置。`start-all.sh` 会先调用 `preflight.sh`，若 RoCE 未配置则自动调用 `setup-roce.sh` 修复。脚本会：

1. 推送 `start-worker.sh` + `worker.env` 到 Worker。
2. 在 Worker 启动容器（先）。
3. 等待 5 秒后在 Head 启动容器（后）。
4. 轮询等待 `Application startup complete`。

> **提示**：`start-head.sh` / `start-worker.sh` 启动时会自动调用 `show_gids` 计算当前 `NCCL_IB_GID_INDEX`，无需在 env 文件里写死。

### 5.2 手动：单独启动 Head / Worker

**Worker 先启动：**

```bash
cd /root/dsv4dspark
./start-worker.sh
```

**Head 后启动（Worker 启动后 3-5 秒）：**

```bash
cd /root/dsv4dspark
./start-head.sh
```

### 5.3 Docker Compose 方式（可选）

如果两台机器都安装了 Docker Compose，可直接使用：

```bash
# Worker
NODE_RANK=1 HEADLESS=1 VLLM_HOST_IP=10.10.12.21 NCCL_IB_GID_INDEX=6 \
  docker compose --env-file worker.env up -d

# Head
NODE_RANK=0 HEADLESS= VLLM_HOST_IP=10.10.12.11 NCCL_IB_GID_INDEX=6 \
  docker compose --env-file head.env up -d
```

### 5.4 启动脚本关键参数

```bash
vllm serve /models/dsv4-abliterated \
  --served-model-name deepseek-v4-flash \
  --host 0.0.0.0 --port 8888 \
  --trust-remote-code \
  --tensor-parallel-size 2 --pipeline-parallel-size 1 \
  --kv-cache-dtype nvfp4_ds_mla \
  --block-size 256 \
  --max-model-len 350000 \
  --max-num-seqs 12 \
  --max-num-batched-tokens 8192 \
  --max-cudagraph-capture-size 72 \
  --gpu-memory-utilization 0.78 \
  --enable-prefix-caching \
  --async-scheduling \
  --enable-chunked-prefill \
  --speculative-config '{"method":"dspark","num_speculative_tokens":5,"draft_sample_method":"probabilistic"}' \
  --tokenizer-mode deepseek_v4 \
  --distributed-executor-backend mp \
  --moe-backend flashinfer_b12x \
  --tool-call-parser deepseek_v4 \
  --enable-auto-tool-choice \
  --reasoning-parser deepseek_v4 \
  --reasoning-config '{"reasoning_parser":"deepseek_v4","reasoning_start_str":"","reasoning_end_str":""}' \
  --default-chat-template-kwargs '{"thinking":false}' \
  --generation-config vllm \
  --enable-flashinfer-autotune \
  --nnodes 2 --node-rank <0|1> \
  --master-addr 10.10.12.11 --master-port 25000 \
  --jit-monitor-mode warn \
  ${HEADLESS:+--headless}
```

## 7. 排障指南

### 7.1 日志检查顺序

1. Worker 日志是否进入 rendezvous：
   ```bash
   docker exec vllm_anemll tail -50 /tmp/vllm-worker.log
   ```
2. Head 日志：
   ```bash
   docker exec vllm_anemll tail -50 /tmp/vllm-head.log
   ```
3. NCCL 走 RoCE 的标志：日志中应出现 `via NET/IB/0`，而不是 `NET/Socket/0`。

### 7.2 常见问题

| 现象 | 可能原因 | 解决 |
|------|----------|------|
| 容器秒退，Exit(2)，log 为空 | 镜像 `ENTRYPOINT` 是 `vllm serve`，原脚本未覆盖 | 启动脚本必须加 `--entrypoint bash`。 |
| Head/Worker 启动后 TCPStore 10 min 超时 | Worker RoCE 口没 IP / 两机 RoCE 不通 | 用 `preflight.sh` 检查；Worker 配 `10.10.12.21/24`。 |
| `ibv_modify_qp failed with 61`，local GID `::` | `NCCL_IB_GID_INDEX` 指向空 GID | 执行 `show_gids`，使用 RoCE IP 对应的 v2 index。 |
| `collective_rpc should not be called on follower node` | Worker 没有 `--headless` | 检查 Worker 启动命令是否含 `--headless`。 |
| `OSError: [Errno 98] Address already in use` | 旧 vLLM 进程占 8888 | 用 `./stop.sh` 或 `sudo fuser -k 8888/tcp` 清理。 |
| `Cannot assign requested address` | `VLLM_HOST_IP` 未设或绑到管理口 | 设为 RoCE IP。 |
| NCCL init 超时 / `ncclCommInitRank -> 2` | GID index 错误、RoCE 未通、防火墙 | 检查 `show_gids`、`ip link`、`iptables`。 |
| 启动卡住 14+ 分钟 CPU 100% GPU 0% | CUDA Graph 死锁 | 加 `--enforce-eager` 作为兜底。 |
| `shm_broadcast` 60s 重复打印 | Worker 在编译/warmup | 正常现象，耐心等待。 |
| 模型加载极慢 | TCP-only NCCL | 检查 NCCL 是否走 IB/RoCE。 |

### 7.3 清理命令

```bash
./stop.sh
```

或手动：

```bash
# Head
sudo docker rm -f vllm_anemll
sudo pkill -9 -f "vllm serve"

# Worker
sudo docker rm -f vllm_anemll
sudo pkill -9 -f "vllm serve"
```

## 8. 踩坑记录

| # | 错误 | 后果 | 修正 |
|---|------|------|------|
| 1 | 使用 NVIDIA / 社区镜像 | `hc_pre` / `Unsupported architecture` 撞墙 | 换 `anemll/dspark-vllm-gx10:0.1.1`。 |
| 2 | Worker 没加 `--headless` | `collective_rpc should not be called on follower node` | Worker 加 `HEADLESS=1` 和 `--headless`。 |
| 3 | `docker exec -d` 后补启动 | 后台进程不生效 / 僵尸 | 直接 `docker run` 启动。 |
| 4 | 漏 `TP_SOCKET_IFNAME` / `GLOO_SOCKET_IFNAME` | PyTorch/GLOO 可能走管理口 | 显式设置为 RoCE 网口。 |
| 5 | `--model` 与 positional 混用 | vLLM 0.25 parser 报错 | 只用 positional：`vllm serve /models/dsv4-abliterated`。 |
| 6 | 双 HCA GID index 多值语法 | NCCL 只取第一个值，导致 QP 失败 | 先用单 HCA 单 GID。 |
| 7 | `VLLM_HOST_IP` 未设 | ZMQ 绑到 WiFi IP，Worker 连不上 | Head/Worker 都显式设为 RoCE IP。 |
| 8 | `VLLM_USE_BREAKABLE_CUDAGRAPH` 未接受 | 镜像自动开启，曾被误判为死锁 | 当前配置可正常运行。 |
| 9 | 进度条 `\r` 不 flush | docker logs 看不到模型加载进度 | 通过 `nvidia-smi` 显存变化判断。 |
| 10 | NetworkManager 清掉 RoCE 地址 | 地址丢失导致 NCCL 失败 | `nmcli dev set X managed no`，并写入持久化配置。 |
| 11 | 未覆盖镜像 `ENTRYPOINT` | 容器秒退 Exit(2)，log 为空 | `docker run` 加 `--entrypoint bash`。 |
| 12 | Worker RoCE 网口无 IP | TCPStore 10 min 超时 | 给 `enp1s0f0np0` 配 `10.10.12.21/24`。 |
| 13 | `NCCL_IB_GID_INDEX` 写死 | `ibv_modify_qp failed 61`，local GID `::` | 以 `show_gids` 实际输出为准。 |
| 14 | 旧进程占 8888 | `Address already in use` | `./stop.sh` 或 `fuser -k 8888/tcp` 清理。 |

- **CUDA Graph 模式**：当前镜像自动开启 `VLLM_USE_BREAKABLE_CUDAGRAPH=1`，可尝试显式设为 0 对比性能。
- **OpenWebUI 接入**：已验证可连，具体配置见第 6.4 节。
